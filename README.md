# Redmi Pad Pro (dizi) ROM bring-up: Evolution X 16/17 and LineageOS 23.2

Custom ROMs for the Redmi Pad Pro (dizi, SM7435 "parrot", Wi-Fi only):
- **Evolution X `bka` (Android 16):** the first line, forked from the official EvoX garnet tree.
- **Evolution X `cnb` (Android 17):** boots, validation clean.
- **LineageOS 23.2 with MindTheGapps (Android 16):** Trebuchet with blur/corner toggles.

All three use the HyperOS **OS3.0.303.0.WNSEUXM** (EEA) vendor blobs and a source-built 5.10 GKI with the stock
modules. The 5G model (ruan) is in [ruan-bringup](https://github.com/rd-trees/ruan-bringup).

- **Build instructions:** [BUILDING.md](BUILDING.md).
- **Install:** [release/INSTALL.md](release/INSTALL.md).
- **Performance work, with measurements:** [research/performance-report.md](research/performance-report.md).

| Path | What |

| `evox-cnb/` | Evolution X `cnb` (Android 17) source, `--reference` to `evox/`; device branch `cnb-dizi` |
| `lineage/` | LineageOS 23.2 source, `--reference` to `evox/`; device branch `lineage-23.2`, MindTheGapps in `vendor/gapps` |
| `<tree>/out-<device>`, `out-release` | Per-device bench out dirs (`out` is a symlink `tools/build.sh` switches) and the release out dir |
| `evox/device/xiaomi/dizi` | Device tree (git, branch `bka-dizi`) |
| `evox/device/xiaomi/dizi-kernel` | Prebuilt stock GKI Image, dtb, dtbo, modules (git) |
| `evox/vendor/xiaomi/dizi` | Extracted blobs (git, generated by `extract-files.py`) |
| `trees/staging` | Clone of the device tree for edits made while a build runs; fast-forward into `evox/device/xiaomi/dizi` afterwards |
| `trees/ref/` | Reference trees (garnet EvoX/Lineage, community dizi/ruan, pipa) |
| `stock/backup/` | **Read-only** dump of all 112 partitions (sha256-verified). Never delete. |
| `stock/OS3.0.303.0.WNSEUXM/` | Stock fastboot ROM (md5 86ca59d4e27bcbb1c43db7acb03c45ca) |
| `stock/dump/` | Extracted stock system/vendor/odm/product/vendor_dlkm |
| `recon/` | Captures from stock HyperOS (props, modules, running devicetree, pen traffic) |
| `tools/` | Bench scripts (below) |
| `logs/<build-id>/` | Flash logs, per-boot captures, validation results |

Soong ignores symlinked directories, so the device/vendor/kernel trees live
inside `evox/` and `trees/device_xiaomi_dizi*` are symlinks *to* them.

## Bench

The tablet is on USB to a Mac reached over ssh, with adb/fastboot in `/opt/homebrew/bin`.
All tools source `tools/env`; the bench host, ssh key and adb serial go in `tools/env.local`.

| Script | Purpose |
|---|---|
| `tools/remote.sh <adb\|fastboot ...>` | Run adb/fastboot on the Mac. adb falls back to Wi-Fi when USB is missing. |
| `tools/build.sh <log> [targets]` | `lunch lineage_<device>-<release>-userdebug` + `m` (default `evolution`; `bacon` on Lineage), log in `logs/<log>.log`. `TREE=evox\|evox-cnb\|lineage`, `DEVICE=dizi\|ruan`, `RELEASE=1` (user, `out-release`) |
| `tools/match-mtimes.py <ref> <dst>` | Give blob-identical files in `<dst>` the mtimes of `<ref>`, so a copied out dir stays incremental |
| `tools/sign-release.sh [name]` | Sign a release target-files with `keys/`, package OTA + fastboot zip (`TREE=`, `DEVICE=`) |
| `tools/push-images.sh <id>` | Stage flashable images on the Mac, verify sha256 |
| `tools/flash-bl.sh <id> [--no-wipe]` | **Preferred.** Bootloader-only flash like Xiaomi's `flash_all.sh`: full `super.img` (`m superimage`), boot images to both slots, wipe, clear `misc`, boot slot a |
| `tools/flash.sh <id> [--wipe] [--slot a\|b]` | `fastboot flashall` (no firmware), default slot b. Needs a working recovery fastbootd (see gotcha 17) |
| `tools/capture.sh <id>` | Watch the boot, classify the outcome, collect logs into `logs/<id>/boot-N` |
| `tools/validate.sh <id>` | Hardware checks; baseline in `logs/stock-hyperos/validate.txt` (0 FAIL) |
| `tools/cam.sh [name]` | Fetch the latest webcam frame of the tablet (Mac runs `~/dizi/cam/camloop.command` in Terminal, frame every 10 s) |
| `tools/recon.sh`, `tools/pen-capture.sh` | Read-only captures from stock |
| `tools/backup.sh` | Full partition dump (needs root) |
| `tools/gen-blobs.py` | Regenerate `proprietary-files.txt` (garnet list + dizi dump + DT_NEEDED closure) |
| `tools/deploy.sh <id> [--wipe]` | Wait for the build, stage (delta against the previous super.img), flash from the bootloader without wiping, wait for boot, adb root |
| `tools/app-sweep.sh <id> [s]` | Launch every launcher app, screenshot, count crashes/ANRs/tombstones |
| `tools/exercise.sh <id>` | Camera (rear/front photo, video), playback, tone, Wi-Fi scan, BT toggle, rotation, brightness, screen off; collects denials. `QUIET=1`: no tone, dim screen |
| `tools/ui-jank.sh <id> [n] [orient]` | Fling Settings/launcher/Chrome and pull QS, hwui + SF timestats. `QS_ONLY=1` for QS only. Discard the first run after a restart |
| `tools/recents-jank.sh <id> [n] [orient]` | Overview (APP_SWITCH) in/out plus card flings, launcher gfxinfo |
| `tools/recents-open-jank.sh <id> [n]`, `tools/recents-ab.sh <id> <label>` | Recents -> app (tap a card), launcher + SF timeline; `RECENTS_TARGETS="Settings Clock"` compares ROMs with the same apps |
| `tools/app-open-jank.sh <id> [n] [label]`, `tools/ab-quick.sh <id> <label>` | Icon -> app and one-line A/B summaries |
| `tools/recents-open-trace.sh`, `tools/launcher-fling-trace.sh` | Perfetto traces; `CFG=tools/perfetto/deep.pbtxt` (sched, kgsl, binder) or `layers.pbtxt` (SF per-layer composition types) |
| `tools/apps.sh`, `tools/ui-tap.sh` | Resolve launcher/browser/clock/gallery per ROM; tap a UI element by label |
| `tools/boot-health.sh <id> [boots]` | Reboot loop: QS jank, dynamic_fps and the panel mode-set count per boot; full capture on bad boots |
| `tools/suspend-watch.sh <id>` | Unplugged deep-sleep monitor over adb-over-Wi-Fi (suspend count, current, wakeup sources) |
| `tools/avc-triples.py <avc.txt>` | Reduce avc denials to unique scontext/tcontext/class rows |
| `tools/boot-kernel-test.sh <id> <Image>` | Repack boot.img with another kernel and `fastboot boot` it once (nothing flashed) |
| `tools/audio-tone`, `tools/audio-rec`, `tools/pen-bond`, `tools/drm-info` | app_process tools: sine tone, mic level (silent), pen bonding, MediaDrm info |

Typical cycle:

```sh
tools/build.sh build-N
tools/push-images.sh build-N
tools/flash.sh build-N --wipe      # --wipe on first flash / encryption changes
tools/capture.sh build-N
tools/validate.sh build-N
```

Updating blobs: `python3 tools/gen-blobs.py trees/ref/evox_garnet/proprietary-files.txt stock/dump evox > evox/device/xiaomi/dizi/proprietary-files.txt`,
then in `evox/`: `PYTHONPATH=$PWD/tools/extract-utils ANDROID_BUILD_TOP=$PWD python3 device/xiaomi/dizi/extract-files.py /build/alex/dizi/stock/dump`.
Check config quickly with `tools/build.sh soong-N nothing` before a full build.

## Device facts

- A/B, virtual A/B, boot header v4, **no init_boot**, super = 9126805504 bytes
  (group `qti_dynamic_partitions`), boot 128 MiB, vendor_boot 96 MiB,
  dtbo 24 MiB, recovery 100 MiB. Stock filesystems are erofs.
- Stock kernel is Google GKI `5.10.246-android12-9` (ab15159037), byte-identical
  to the ROM's boot.img. Newer certified GKI (5.10.257, `android12-5.10-2026-07_r1`)
  should drop in via KMI stability — untested (Stage B).
- Vendor is Android 14 based: `ro.board.api_level` 31, VNDK 32.
- Touch: Novatek NT36532 SPI (`nt36532_spi`, `lct_tp`, `xiaomi_touch`), also in
  the recovery module list. Hall sensor `xiaomi-hall` reports `SW_LID`.
- Wi-Fi: WCN6750 probes as **qca6750** (not garnet's adrastea): config and MAC
  link live under `qca_cld/qca6750`.
- Sensors: accel, gyro, mag, light, steps. No proximity, no vibrator.
- Kernel source: MiCode `ruan-u-oss` has dizi build configs and the touch
  drivers, but no dizi board DTS (running DT dumped to `recon/running.dts`).
- ramoops: 512 KiB console + 1 MiB pmsg at 0x80d00000 → `/sys/fs/pstore`.
- Pen protocol: see `recon/pen/FINDINGS.md`.

## Gotchas (things that already bit us, or will)

1. **USB after boot.** The dwc3 controller often misses the attach after an
   Android boot (`/sys/class/udc/a600000.dwc3/state` = `not attached`, Mac
   sees nothing; fastboot is unaffected). Fix: `echo none` then
   `echo peripheral` to `/sys/devices/platform/soc/a600000.ssusb/mode`.
   HyperOS: Magisk `/data/adb/service.d/adb-tcp.sh`. EvoX: `init.dizi.usb_attach.sh`, early (from adbd) on
   debuggable builds and at boot_completed on all builds (f32ec4b; release-1 lacks it, so it needs a replug).
2. **macOS Local Network privacy** blocks Homebrew `adb` from LAN addresses
   ("No route to host"). `~/dizi/adb-wifi-relay.sh` on the Mac relays
   `127.0.0.1:15555` → tablet `:5555` through Apple's `nc`. adb over TCP is
   still RSA-authenticated.
3. **garnet's "RIL" blob section** also holds platform daemons dizi needs
   (`pd-mapper`, `rmt_storage`, `tftp_server`, `qti`, `netmgrd`). Only the
   modem/IMS daemons are skipped.
4. **Duplicate module names** in the blob list (same basename in `lib64/` and
   `lib64/egl/`, `-ndk_platform` stubs, protobuf vendorcompat `stem:`) break
   Soong; `gen-blobs.py` handles the known cases.
5. **xiaomi_touch ioctl layout** is `int buf[256] = {0, mode, value}`.
   LineageOS pipa's `{mode, value}` does not work on this driver.
6. **Editing the tree during a build** can mix old and new files into that
   build. Use `trees/staging` and merge afterwards.
7. **Never flash firmware from builds, never `flash_all_lock`, never relock**
   the bootloader on a custom ROM. EDL needs an authorised Xiaomi account.
8. **Both slots have OS3.0.303 firmware** (slot a synced 2026-09-26, verified).
   If Xiaomi firmware is ever updated, blobs, kernel and firmware must be
   re-extracted from that same build, and both slots kept in sync.
9. **Anti-rollback** is 1 on device and ROM. Check `fastboot getvar anti`
   against `images/anti_version.txt` before flashing any older stock ROM.
10. **Leaving HyperOS wipes data.** The first EvoX flash needs `--wipe`
    (different FBE keys); going back to HyperOS needs `flash_all.sh`
    (not `_except_storage`). Magisk and its boot scripts disappear with it.
11. **Virtual A/B merges.** If fastbootd refuses to flash super after an OTA,
    run `fastboot snapshot-update cancel` first.
12. **`flashall` owns the recovery partition.** It replaces OrangeFox on the
    target slot with the EvoX recovery (which has touch, display and adb).
    OrangeFox (`recovery.img`, garnet-derived binary) can be re-flashed to
    `recovery_<slot>` for debugging.
13. Xiaomi's `flash_all*.sh` uses `grep -oP`, which macOS grep lacks; the anti
    check silently passes there. Check anti manually.
14. **Kernel UAPI headers** come from `kernel/xiaomi/sm7435` *and*
    `kernel/xiaomi/sm7435-modules` (its Makefile's `headers_install` pulls the
    display/audio/video uapi from `../sm7435-modules`). Both are synced
    headers-only; without the modules repo the display HAL fails on `sde_drm.h`.
    The generated headers are cached in
    `out/soong/.intermediates/vendor/lineage/build/soong/generated_kernel_includes`
    and only track the kernel dir: after changing `sm7435-modules`, delete that
    directory or the stale copy is reused (this is what broke build-9).
    ABI check (2026-09-26): garnet's `sde_drm.h`/`msm_drm_pp.h` are identical to
    Xiaomi's dizi/ruan source (`MiCode/vendor_opensource_display-drivers@ruan-u-oss`);
    `mmm_color_fmt.h` differs only by a redundant `break`. `mi_disp.h` differs but
    nothing we compile uses it. Audio-kernel has no published ruan branch; audio
    userspace (agm/pal) is dizi blobs, so a garnet/dizi audio uapi mismatch would
    show only at runtime: **check audio first if it fails while the HAL is up**.
15. **Wireless/Play**: unlocking already drops Widevine to L3 on most Xiaomi
    devices; Play Integrity is out of scope.
16. **Local patch in `vendor/gms`** (4ee211d, on top of upstream bka 89c3940):
    `CrossDeviceAccessServicePrimary` declares `org.apache.http.legacy` as an
    optional uses-library that its APK does not, so `manifest_check` fails
    (build-10). Re-apply after `repo sync` if upstream still has it.
18. **macOS asks before a new USB accessory connects** (Apple silicon).
    Bootloader fastboot, fastbootd, recovery adb and Android adb are different
    USB identities; each new one waits for "Allow" on the Mac and looks like a
    dead USB link. This, not the recovery, stranded the build-12 flash. For
    unattended work set System Settings > Privacy & Security > Allow
    accessories to connect > Always.
17. **`flashall` depends on our recovery.** Logical partitions can only be
    written from fastbootd (inside recovery), so `fastboot flashall` reboots
    into the freshly flashed recovery mid-flash. build-12's fastbootd was
    actually fine; the Mac was waiting for accessory approval (gotcha 18). `reboot fastboot`
    also leaves a boot-fastboot command in `misc`, so every reboot returns to
    recovery until `misc` is cleared (`flash misc` with the stock zero image).
    Use `flash-bl.sh`. Our `super.img` holds data only in the `_a`
    partitions (virtual A/B), so it must boot slot a.
19. **Never pre-format userdata.** `/data` uses metadata encryption, so vold
    must create the filesystem inside dm-default-key. `fastboot -w` from the
    Mac formats ext4 on the raw partition; fs_mgr then sees a non-wiped
    partition, calls `vdc cryptfs mountFstab`, vold finds no key
    (`read_key failed in mountFstab`) and init reboots; after 7 tries the
    bootloader marks the slot unbootable and stops in fastboot (build-13
    boot-1). Use `fastboot erase userdata` (flash-bl.sh does), or zero the
    first 64 MiB from OrangeFox. Boot logs survive in the `oops` partition
    (mtdoops, `/dev/block/by-name/oops`, 7 records) even when pstore is empty.
20. **Local patch in `system/core`** (c96203e): EvoX's init.rc wiped
    `/data/resource-cache` when `persist.sys.is_upgrade=1`, racing with
    OverlayManagerService. On the first boot after every dirty flash or OTA,
    all static overlays (ours, Pixel config, recents component) were
    `STATE_NO_IDMAP`: Pixel Launcher lost its recents permissions and crashed
    on rotation, and device overlays and the pen key handler were not applied.
    Before b19, reboot once after flashing before testing anything.
21. **Local patch in `frameworks/native`** (0771ce4): Vulkan RenderEngine
    asks for REALTIME queue priority when the Adreno driver doesn't answer
    the global priority query. GL stays the default; see
    research/vulkan-adreno710.md.
22. **A `dontaudit` is still a denial once enforcing.** On b21 I dontaudited
    `hal_thermal_default dac_read_search` as noise. Under enforcing (b24) the
    thermal HAL then reported no temperatures: GameBar's init.gamebar.rc makes
    two zone temp nodes system:system 0660. Before adding a dontaudit, check
    the function under `setenforce 1`. Kernel read order: dac_read_search is
    tried first, then dac_override.
23. **Staging is a delta.** The Mac is on a ~4 MB/s VPN link.
    `push-images.sh` seeds `super.img` from the newest staged one (APFS
    clone) and rsync sends only the changed blocks, 0.2–0.4 GB of 4 GB.
    rsync `-z` fails against macOS openrsync; use `ssh -C`.
25. **Kernel defaults (since fa2e529):** the source-built GKI Image (`Image-source`) and the source
    `msm_drm.ko` with the splash-timing fix. `DIZI_SOURCE_KERNEL=false` and `DIZI_SOURCE_DISPLAY=` (empty)
    select the stock prebuilts. The XiaomiParts 60->120 Hz round trip stays as a backstop
    (`settings put global dizi_refresh_kick 0` disables it).
26. **Releases.** `RELEASE=1 tools/build.sh <id> target-files-package otatools` builds a `user`
    variant in `evox/out-release` (no insecure adb, no bench adb key). `tools/sign-release.sh` signs it
    with the private keys in `keys/` (app keys, one 4096-bit key per APEX, generated on demand, and
    `avb.pem` for vbmeta) and writes the signed OTA zip plus the fastboot package (images,
    `release/flash-dizi.sh`, INSTALL.md) to `release/out/<name>/`. **Back up `keys/` and never commit
    it:** updates only install over builds signed with the same keys.
    Signing needs the `build/make` releasetools fix 504650b (`PartitionMapFromTargetFiles` got a
    target-files zip and crashed); rebuild the host tools after changing releasetools, since
    `sign_target_files_apks` etc. are bundled Python binaries in `out-release/host`.
27. **Build archive.** `tools/archive-build.sh <id>` keeps a build's flashable images in `builds/<id>`,
    and `push-images.sh`/`deploy.sh` use it, so a later build in `out/` can't replace an unflashed one.
28. **Pixel Launcher taskbar pinning.** The setting lives in the launcher's device-protected prefs,
    `/data/user_de/0/com.google.android.apps.nexuslauncher/shared_prefs/boot_aware_prefs.xml`
    (`TASKBAR_PINNING_KEY`, `TASKBAR_PINNING_DESKTOP_MODE_KEY`), not in the AOSP name
    `com.android.launcher3.device.prefs.xml`. The UI toggle hangs off the taskbar divider, which only shows
    when non-dock recent apps are present. If you edit the file by hand, stop the launcher first and keep
    the MLS label (`privapp_data_file:s0:c512,c768`): `sed -i` drops the categories and the launcher can
    no longer write it (the toggle gets stuck). During testing (2026-09-28) the pinning option appeared
    after I wrote a prefs file under the AOSP name and restarted the launcher; whether that or the restart
    exposed it is unresolved. Reverted to unpinned; release docs describe the manual toggle.
24. **Measure jank on warm runs.** The first QS/app run after `stop; start`
    or a boot compiles shaders and is 1.5–2x worse. Discard it.

## Restoring stock

```sh
# On the Mac, from the extracted fastboot ROM directory (copy it there first):
./flash_all.sh            # wipes data; NOT flash_all_lock.sh
```

Per-partition images (including `persist`, `modemst1/2`, `fsg`) are in
`stock/backup/` if anything device-specific is ever damaged.
